## Краткое резюме

Цель: разработать приватный плагин Sieve, который отсекает файлы до индексации Obsidian, полностью воспроизводит matcher Syncthing 2.1.6 и дает отдельное отображаемое имя каждому хранилищу.

Рекомендуемый подход: сначала доказать ранний фильтр в настоящем жизненном цикле приложения; затем общий TypeScript matcher и изолированные адаптеры платформ. На мобильных устройствах проверить замену начального нативного массового обхода на управляемый обход через доступный адаптер, не меняя нативную установку. Это кандидат, а не подтвержденная архитектура.

Критический контекст начала: движка, UI и устанавливаемой версии не было. Сейчас общий matcher реализован. Desktop bundle показывает раннюю загрузку плагинов, но мобильный `watchAndStatAll` может уже прочитать все поддерево до обработки JS-результата. Рабочий фильтр индекса после такого вызова не выполняет основное требование.

Вероятно затронутые области: `src/core/`, `src/platform/`, `src/settings/`, `src/ui/`, `src/i18n/`, `src/alias/`, `src/main.ts`, `Tests/`, `Tools/`, документация, конфигурация сборки. Пути будущих модулей ниже — ориентиры для соответствующих этапов; общий core уже существует.

Ограничения: исходники остаются в прежнем Projects; без зеркала, новой синхронизации, удаления файлов, переименования корня, Node/Electron в общем или мобильном runtime. EN/RU обязательны. Основное RU описание: «Исключает файлы и каталоги перед индексацией хранилища»; EN: «Excludes files and folders before vault indexing». Использовать растущую версию разработки и номер сборки; публичную release-version, лицензию и публичность назначает Constantine отдельно.

Проверка: нативный oracle, трассировка обхода и I/O, проверка индекса и кеша метаданных, реальные desktop/mobile приложения, сохранение/переименование/вложения/внешние правки, обратимость, измеренный пилот.

Решения Constantine: обычная растущая версия разработки вместо test-manifest заглушки; правила через UI или конфиг плагина; применение после переоткрытия с предложением перезагрузки после успешного UI-сохранения; RU для русского Obsidian, EN для остальных. Доступны iPhone, iPad и удаленные Linux-хосты, помимо локального Windows; mobile vault хранится в локальной папке. Согласованы alias всех пунктов меню переключения и одна предыдущая рабочая конфигурация для восстановления при ошибке. Constantine разрешил продолжать разработку по API/коду и явно отмеченным гипотезам там, где native проверка недоступна. Это разрешает общий matcher до завершения всех гейтов; доказательства поддержки платформ по-прежнему нужны отдельно.

## 1. Задача и ожидаемый результат

Sieve управляет видимостью в индексе и начальным обходом, не превращает файловый адаптер в ограничитель доступа и не изменяет способ записи документов или синхронизации. Прямое чтение доступного файла приложением должно сохраняться, особенно для конфигурации и `#include`.

Для каждого пути matcher воспроизводит результат Syncthing 2.1.6, включая признаки ignored, deletable, case-folded и `CanSkipDir`. Runtime игнорирует возможность удаления: `(?d)` остается семантикой matcher, а не разрешением выполнять filesystem delete.

Исключенный каталог с `CanSkipDir=true` не обходится. Если разрешенные потомки возможны, каталог обходится как необходимый контейнер; разрешенные файлы и цепочка их родительских каталогов доступны индексу. Классификация пути и решение об обходе — отдельные результаты. Нельзя применять правила gitignore или считать каждое совпадение каталога основанием для pruning.

Поддержка Windows, macOS, Linux, iOS и Android является целью. Для каждой платформы нужны отдельные доказательства; настольная эмуляция mobile и наличие Capacitor-кода в desktop bundle их не заменяют. Если одна платформа не проходит гейт, нельзя молча заменить согласованный результат desktop-only версией.

У каждого vault собственные данные плагина, правила и alias. Alias меняет согласованные UI-поверхности, а не путь, идентификатор хранилища, URI, папку или настройки других vault.

### Oracle и неточности, которые нельзя переносить в движок

Проверены первичные исходники фиксированного `v2.1.6`: [ignore.go](https://github.com/syncthing/syncthing/blob/v2.1.6/lib/ignore/ignore.go), [ignore_test.go](https://github.com/syncthing/syncthing/blob/v2.1.6/lib/ignore/ignore_test.go), [ignoreresult](https://github.com/syncthing/syncthing/blob/v2.1.6/lib/ignore/ignoreresult/ignoreresult.go), [scanner/walk.go](https://github.com/syncthing/syncthing/blob/v2.1.6/lib/scanner/walk.go). Онлайн [справка](https://docs.syncthing.net/users/ignoring.html) — дополнение; при расхождении приоритет у pinned-кода и запуска oracle.

- `Match` и `allowsSkippingIgnoredDirs` в `ignore.go:91–108,218–267` дают отдельный признак безопасного pruning; нативный scanner проверяет его, а не только факт ignored.
- `ignore.go:504–507` дедуплицирует одинаковые строки до обработки директив. Повтор идентичной строки `#include` и повтор доступа к файлу через другой путь нельзя описывать одним безусловным правилом ошибки; `loadParseIncludeFile:323–336` отдельно выявляет повтор уже прочитанного файла.
- `#escape` проверяет число собственных масок без масок из include (`485`); уточнить формулировку «перед правилами» на проверенных примерах.
- Нативные проверки содержат Unicode, CRLF, пустые/ошибочные маски, prefix order, automatic case-insensitivity, duplicate lines, частичную директиву include, escaping и `TestSkipIgnoredDirs`. Портировать только таблицу масок из справки недостаточно.
- `Match` обрабатывает внутренние/временные имена Syncthing до обычных масок; это надо включить в oracle, а обязательный обход конфигурации Obsidian реализовать отдельным слоем runtime.
- `loadParseIncludeFile` допускает выход из базового каталога для Basic filesystem. Не вводить молча более узкую совместимость: доступ определяется правами/возможностями платформы, недоступное подключение возвращает ошибку. Не расширять права и не обходить sandbox.

### Рабочие технические допущения

- Конфигурация принадлежит текущему `vault.configDir`, который может отличаться от `.obsidian`; внутри нее не должно быть побочных фильтров доступа. При правилах `*` Obsidian по-прежнему читает/пишет настройки и загружает плагины, но конфигурация не обязана попадать в обычный контентный индекс.
- Host adapter остается владельцем записи, rename, удаления по явному действию пользователя и watcher. Sieve не меняет разрешения/ACL и не вводит новый синхронизатор.
- Общий matcher детерминирован, не использует `process.platform`, Node fs/path, Electron, сети, внешние сервисы или global prototype patches. Параметры платформы и чтение include передаются явно.
- В минимальном безопасном варианте применяется полностью скомпилированная неизменяемая ревизия; ошибка не публикует частичный matcher и не удаляет индексные объекты через файловую операцию. Как показывать сохраненную, ожидающую и активную ревизии, зависит от решения о применении.
- Стартовые измерения и тесты не включают оригинальный Projects до завершения пилота. Реальные устройства и конкретные версии приложений еще не доступны как проверенное доказательство.

## 4. Рассмотренные варианты

Архитектурная развилка относится к раннему обходу, а не к оформлению UI.

| Вариант | Усилие | Плюсы | Минусы/риски | Когда выбирать |
| --- | --- | --- | --- | --- |
| Публичный early-filter API Obsidian | S при наличии; срок его появления неизвестен | Стабильный контракт, меньше private hooks | В просмотренных типах подходящий контракт не найден; нельзя планировать его появление | Если spike обнаружит действующий контракт с доказанным pruning на всех требуемых платформах |
| Guard экземпляра desktop adapter; на mobile проверенная управляемая рекурсия вместо массового native scan | M–L, сначала 3–6 дней spike | Сохраняет файлы/права/запись; общий matcher; потенциально отсекает I/O до индекса | Private contracts, события и повторная синхронизация, потеря преимуществ быстрого native scan; мобильный watcher может сам обходить все | Рекомендуемый кандидат при прохождении гейтов ниже |
| Фильтрация готового индекса/результата `watchAndStatAll`, скрытие explorer | S–M | Проще показать видимость и скрыть технические файлы | Лишний обход уже выполнен; основной результат не достигнут | Отклонить как реализацию основной функции; допустимо только как диагностическое сравнение |

Свой TypeScript matcher с differential oracle — выбранный путь в рамках требований, а не повод выбирать «похожую» glob/gitignore-библиотеку. Go executable допустим только как инструмент тестирования; Go/WASM или native binary в самом плагине не вводить без новой архитектурной необходимости и решения пользователя.

## 6. Общая проверка и критерии приемки

### Гейт архитектуры до основной реализации

1. Установленный и заранее включенный тестовый Sieve завершает подготовку правил/hook до первого контентного обхода. Это доказано журналом lifecycle на реальном приложении, минимум при двух очередностях community plugins, без задержки через `onLayoutReady`. Первый запуск без ранее включенного плагина фиксируется отдельно: фильтрацию до загрузки собственного плагина обещать нельзя.
2. На fixture с известными запрещенными поддеревьями их содержимое дает **0** операций перечисления/статирования/чтения по инициативе scanner и **0** контентных объектов в индексе/metadata cache. Чтение имени технического каталога при `readdir` его родителя допустимо. Проверка исключает собственный заранее выполненный fixture census, чтение правил и требуемой конфигурации.
3. На fixture с include-потомком результат соответствует exhaustive oracle-walk без pruning, цепочка родителей доступна; ранний skip, теряющий разрешенный файл, означает no-go.
4. Mobile fast и fallback paths проверены по отдельности. Если после JS guard native watcher/stat остается полным, гейт I/O не пройден. Перевод на рекурсию проверяет стоимость/полноту watcher и поведение resume, а не только готовый индекс.
5. Старт с cached metadata от нефильтрованного vault не возвращает исключенные пути в metadata/search/graph. В штатной конфигурации и alternate `configDir` приложение и другие плагины работают при `*`; Sieve не вызывает filesystem delete/rename/write для исключения контента.
6. На синтетическом большом vault с не менее 95% файлов в полностью исключаемых поддеревьях собственные посещения scanner сокращаются минимум на 90%; медиана `Reading files` — минимум на 30% относительно baseline. На небольшом vault старт не ухудшается более чем на 10% или 100 ms, выбирается больший допуск. Это предлагаемый инженерный гейт для spike, не гарантированное ускорение любого Projects; если устройства не проходят, оценить измеренную стоимость и пересогласовать ожидание до реализации.
7. Hook можно снять без остаточной подмены чужих wrappers. После полного открытия без Sieve baseline индекс восстанавливается, хеши исходных документов не меняются. Неуспех хотя бы по целостности, раннему I/O или mobile обходу запрещает объявлять общий go.

### Сквозное принятие результата

- Весь переносимый upstream-корпус и дополнения дают 0 различий для match flags, ошибок и traversal. Platform-specific cases проверены настоящим oracle на подходящих ОС; пропуски перечислены и не называются PASS.
- Нативный oracle повторяем: upstream SHA/tag, версия Go, glob dependency revision, OS/build flags, UTF-нормализация, входные файлы и seed генератора зафиксированы. Эталон не вычисляется TypeScript-движком Sieve.
- Все позитивные разрешения сохраняются; `(?d)` не приводит к удалению. За пределами явно выполняемых пользователем редактирований сохранены хеши/список файлов fixture.
- EN/RU ключи и placeholders совпадают, точные согласованные RU фразы сохранены. Основные настройки не содержат Syncthing; полная справка содержит совместимость, синтаксис и ошибки.
- Настройки разных vault изолированы; saved и active состояния не смешаны. Alias не меняет физическое имя/URI/идентичность.
- Каждая объявленная платформа имеет отчет реального хоста с точной версией, способом хранения vault, startup/watch/resume и статусами PASS/FAIL/NOT_TESTED.

## 7. Риски, критерии остановки и заметки для выполнения

- Private hooks ломаются при обновлении Obsidian. Capability probe проверяет используемые методы/форму результатов до установки; один номер версии недостаточен. При несовместимости не устанавливать частичный фильтр и показывать точное «Эта версия Obsidian не поддерживает фильтрацию Sieve».
- Публичный API и native mobile watcher могут не позволить настоящий pruning. Отсутствие доказуемого раннего отсечения — no-go, а не разрешение выпускать медленный projection под тем же обещанием.
- На первой установке плагин еще не был включен при старте. Документировать необходимость полного повторного открытия; отдельно проверить Restricted mode, включение/выключение после старта, аварийный запуск и смену vault.
- Ошибка include/escape/UTF-8 или недоступный путь не должна незаметно менять разрешения/индекс. Ошибку компиляции возвращать явно; last-known-good и поведение первого ошибочного запуска согласовать вместе с применением. Рекомендуется сохранить прежнюю рабочую ревизию; при ее отсутствии оставить обычное поведение хоста с явным сообщением, не зависать на старте.
- Не подменять все filesystem read/write ради фильтра: direct read include и config обязан работать. Изоляция экземпляра, restoration по принадлежности wrappers и teardown watcher/таймеров обязательны.
- Сканирование исключенного контейнера ради разрешенного потомка, Unicode case folding, нестандартный configDir, symlink/junction и cached metadata — наиболее вероятные источники скрытой потери данных в индексе.
- Alias через `getName()` может влиять на плагины, имя окна и внешние команды. Предпочтительны отдельные UI-точки с проверенной семантикой; стартовый менеджер вне загруженного vault может быть недоступен плагину.
- Оригинальный Projects подключается только после зеленого пилота и отдельного решения о переходе; перед этим фиксируются конфигурация, rules hash и доступный проверенный recovery. Нельзя сканировать, менять или очищать остальные Projects в рамках подготовки.
- В этой задаче создается только план. Mira не устанавливает зависимости/плагин, не меняет исходники, не запускает native pilot, не делает commit, push, tag, release или public visibility. John проверяет и коммитит согласованный общий результат.
