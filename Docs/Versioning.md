# Версии и сборки Sieve

## Источник

`package.json` хранит текущую версию разработки `version` и целочисленный `sieveBuild`. Отображаемый формат — `X.Y.Z (N)`. Копия `X.Y.Z` в `manifest.json` совпадает с package; `versions.json` сопоставляет версии минимальной версии Obsidian. Устанавливаемые пробы используют эту же версию, без отдельной числовой заглушки.

До первого публичного релиза X равен 0. Версия развивается вместе с исходниками, счетчик сборок растет; при подготовке релиза Constantine назначит его версию отдельно. Назначение версии не является публикацией.

Схема следует проверенному проектному правилу Fantasy Football: `X.Y.Z (build N)`, major 0 до первого релиза, Y для возможностей, Z для исправлений, N для новых недокументальных ревизий. Sieve использует свой согласованный формат отображения без слова build.

## Правила проекта

- X задает Constantine; до первого публичного релиза используется 0.
- Y увеличивается при новой возможности; Z — при исправлении. При увеличении верхней части нижние сбрасываются.
- N увеличивается для каждого недокументального коммита/новой сборки исходников. Повторная компиляция того же SHA сохраняет номер; docs-only изменения его не повышают.
- Каждая новая недокументальная ревизия повышает Y или Z и N. Повторная сборка неизмененных исходников не создает новую версию. Номер сборки не сбрасывается при назначении релиза.
- Версионный коммит начинается с `X.Y.Z (N)`. Документальный коммит может не иметь версионного префикса.

Сборщик устанавливаемого пакета сохраняет fingerprint исходников, импортированных в пакет материалов, toolchain и build config в `dist/sieve/identity.json`. Неимпортированная документация в fingerprint не входит. Если fingerprint изменился, следующая сборка требует строго большего `X.Y.Z` и `sieveBuild`; ошибка проверяется до перезаписи main.js. Повторная сборка неизмененного исходного состояния сохраняет номер. При приватной упаковке Git SHA должен совпадать с текущим локальным коммитом; dirty-сборка в ZIP не допускается.

## Требования Obsidian

Manifest и тег релиза используют только `X.Y.Z`: без `v`, номера сборки, суффикса prerelease или build metadata. Имя релиза может содержать `X.Y.Z (N)`. Нельзя переиспользовать опубликованный тег для другой сборки.

Для релиза нужны `main.js`, `manifest.json` и при наличии `styles.css`; совместимость в `versions.json` обновляется вместе с версией. До установки и реальных проверок нельзя выдавать заготовку за рабочий релиз.

Источник: [публикация плагинов Obsidian](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin), [схема manifest](https://docs.obsidian.md/Reference/Manifest).

## Начальное состояние

Первая диагностическая сборка — `0.2.0 (2)`. Сборка 1 уже использовалась в исторической заготовке `ca07e63`; счетчик не переиспользуется. Релиз и тег не создавались. Репозиторий остается приватным; публикация первой версии и лицензия требуют отдельного решения владельца.
