# Настройки Sieve

Настройки принадлежат отдельному хранилищу. UI и ручная правка используют `<configDir>/plugins/sieve/data.json`, обычно `.obsidian/plugins/sieve/data.json`.

```json
{
  "schemaVersion": 1,
  "rules": "(?i){node_modules,build,dist}",
  "displayName": ""
}
```

`rules` — текст правил. Несколько строк в JSON разделяются `\n`; синтаксис описан в [справке](Syntax.ru.md). `displayName` сохраняет отображаемое имя; применение к меню разрабатывается отдельно. Пустое значение означает имя корневой папки. Корневая папка и ID хранилища сохраняются.

Сохраненные правила применяются после полного повторного открытия. UI проверяет правила и все подключаемые файлы до записи; успешное сохранение предлагает перезагрузку. При выборе «Позже» текущий набор правил остается активным. При первой установке или включении после загрузки хранилища также нужно переоткрытие.

Русский язык Obsidian выбирает RU, любой другой — EN. Справка доступна без сети. Форма различает черновик, сохраненные и активные правила; пока настройки загружаются, поля и сохранение недоступны. Сообщения об ошибках указывают строку и источник, включая файлы `#include`.

## Рабочая конфигурация

При сохранении измененных настроек плагин хранит одну предыдущую подтвержденную рабочую конфигурацию в `data.previous.json`, включая байты подключаемых файлов. Последующие сохранения заменяют этот снимок; истории копий нет. Сохранение неизменных правил и includes ничего не записывает.

При ошибке на следующем запуске Sieve использует валидный предыдущий снимок и показывает сообщение. Если его нет или он поврежден, хранилище открывается без фильтрации. При ручной офлайн-правке предыдущий снимок может еще отсутствовать: плагин не может восстановить уже перезаписанную конфигурацию.

## Отключение

После отключения полностью переоткрой хранилище, чтобы вернуть обычный индекс. Файлы остаются на диске. Приватные сборки проверяются в отдельных тестовых хранилищах; текущая матрица платформ — [Compatibility](Compatibility.md).
