# Настройки Sieve

Настройки принадлежат отдельному хранилищу. UI и ручная правка используют `<configDir>/plugins/sieve/data.json`, обычно `.obsidian/plugins/sieve/data.json`.

```json
{
  "schemaVersion": 1,
  "rules": "(?i){node_modules,build,dist}",
  "displayName": ""
}
```

`rules` — текст правил. Несколько строк в JSON разделяются `\n`; синтаксис описан в [справке](Syntax.ru.md). `displayName` задает подпись текущего хранилища, заголовок окна и имя каждого vault в меню переключения и поиске. Пустое или пробельное значение использует имя корневой папки. Путь, корневая папка, ID и URI хранилища сохраняются. Доступность поверхностей зависит от версии и платформы; проверенные границы — [README](../README.md#платформы).

Успешное сохранение имени обновляет доступные UI-подписи; черновик и ошибка Save их не меняют. Имена других vault берутся из их собственных конфигов; недоступный или некорректный конфиг оставляет исходную подпись. Их правила при чтении имени не компилируются. Стартовый менеджер до загрузки плагина использует нативные имена.

Сохраненные правила применяются после повторного открытия. UI проверяет правила и все подключаемые файлы при уходе из поля и перед записью; успешное сохранение предлагает перезагрузку. При выборе «Отложить» текущий набор правил остается активным. При первой установке или включении после загрузки хранилища также нужно переоткрытие.

Русский язык Obsidian выбирает RU, любой другой — EN. Для загруженного Sieve описание в списке установленных плагинов тоже локализуется; до загрузки и после отключения используется английское описание из manifest. Справка доступна без сети.

Страница настроек и ее пункт меню используют одну штатную иконку Lucide `layers`. Подзаголовка с описанием плагина на странице нет. Правила и примеры синтаксиса объединены в штатную карточку Obsidian с разделителем. Размеры текста, внутренние отступы карточки и разделитель задает Obsidian. Краткие примеры не повторяют пояснение после строки комментария; отключенные кнопки не реагируют на наведение.

Форма различает черновик, сохраненные и активные правила. Закрытие страницы настроек сбрасывает несохраненные правки. «Сохранить» недоступно без изменений, во время загрузки или сохранения и при известной ошибке правил; после исправления правила проверяются повторно. Ошибки показаны под полем: номер строки и причина, а для `#include` также имя файла. Статус сохранения и применения отображается отдельными строками в блоке «Статус».

## Рабочая конфигурация

При сохранении измененных настроек плагин хранит одну предыдущую подтвержденную рабочую конфигурацию в `data.previous.json`, включая байты подключаемых файлов. Последующие сохранения заменяют этот снимок; истории копий нет. Сохранение неизменных правил и includes ничего не записывает.

При ошибке на следующем запуске Sieve использует валидный предыдущий снимок и показывает сообщение. Если его нет или он поврежден, хранилище открывается без фильтрации. Сохранение исправленного конфига после fallback предлагает переоткрытие даже при совпадении правил с активным снимком; до него индикатор восстановления сохраняется. При ручной офлайн-правке предыдущий снимок может еще отсутствовать: плагин не может восстановить уже перезаписанную конфигурацию.

## Отключение

После отключения полностью переоткрой хранилище, чтобы вернуть обычный индекс. Файлы остаются на диске. Приватные сборки проверяются в отдельных тестовых хранилищах; границы поддержки платформ описаны в [README](../README.md#платформы).
