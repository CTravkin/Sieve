# Синтаксис фильтров

[Русский](Syntax.ru.md) · [English](Syntax.en.md)

Эталон Sieve — Syncthing 2.1.6. Общий matcher сравнен с нативным oracle на Windows и Linux без расхождений в проверенном корпусе. Интеграция с Obsidian и остальные платформы проверяются отдельно; pin и команды описаны в [Oracle](../scripts/Oracle/README.md).

## Порядок правил

Правила проверяются сверху вниз. Первое совпадение определяет результат. Обычная маска исключает путь, префикс `!` разрешает. Если совпадений нет, путь разрешен.

Пути отсчитываются от корня хранилища. Правила без начального `/` совпадают в корне и на любой глубине; начальный `/` ограничивает правило корнем. `node_modules` совпадает с файлом или каталогом такого имени и его содержимым. `node_modules/` совпадает с содержимым, но не самим каталогом.

Пустые и повторяющиеся одинаковые строки пропускаются; пробелы по краям убираются, внутри имени сохраняются. Строка комментария начинается с `//`. Комментарии после маски и строки `# comment` не являются комментариями.

## Маски

| Запись | Значение |
| --- | --- |
| `*` | Любая последовательность символов, кроме разделителя пути |
| `**` | Любая последовательность символов, включая разделители |
| `?` | Один символ, кроме разделителя |
| `[abc]` | Один из перечисленных символов |
| `[a-z]` | Один символ из диапазона |
| `[!a-z]` | Один символ вне диапазона |
| `{md,txt,pdf}` | Одна из перечисленных альтернатив |

Это маски, а не регулярные выражения. Нативный matcher Syncthing 2.1.6 сопоставляет `a/**/b` как с `a/b`, так и с `a/x/b`: поведение зависит от его glob-оптимизатора. Начальный `**/` дополнительно обрабатывается для совпадения в корне.

## Префиксы

`!` разрешает совпавший путь. `(?i)` включает сопоставление без учета регистра. Syncthing на Windows и macOS сопоставляет без учета регистра по умолчанию; для переносимых правил указывайте `(?i)` явно.

`(?d)` разрешает Syncthing удалять исключенный файл, когда он мешает удалить родительский каталог. Префикс не меняет совпадение маски. Sieve принимает его для совместимости; применение правил Sieve не удаляет файлы.

Префиксы можно указывать в любом порядке, каждый не более одного раза: `(?i)!*.md`, `(?d)(?i)*.tmp`. Запись `(?di)` их не объединяет.

## Подключение файлов

```text
#include filters/common.stignore
```

Правила подключенного файла вставляются на место директивы. Для главного списка путь подключения отсчитывается от корня хранилища, для вложенных подключений — от каталога подключающего файла. Сами маски всегда относятся к корню хранилища. Файл должен быть доступен приложению; отсутствие файла считается ошибкой.

Одинаковые строки дедуплицируются глобально, в том числе директивы `#include`. Поэтому точный повтор директивы может быть пропущен. Повторное подключение файла через другую, не отброшенную директиву вызывает ошибку `multiple include`.

Файлы правил используют UTF-8. Каждый подключенный файл имеет собственный символ экранирования.

## Экранирование

По умолчанию Windows использует `|`, другие платформы — `\`. Для одинакового текста правил можно явно задать символ:

```text
#escape=\
```

Директива задается один раз в каждом файле перед его собственными масками; перед ней могут находиться подключения `#include`. Символ должен быть ровно один. При `#escape=\` используйте `/` для разделителей путей; `\{draft\}.md` обозначает буквальное имя `{draft}.md`. В обычном режиме Windows эквивалент — `|{draft|}.md`. Экранированный символ экранирования обозначает его самого.

## Белый список

```text
// Технические каталоги
(?i){node_modules,build,dist}

// Разрешенные форматы
(?i)!*.{env,md,markdown,base,canvas,pdf,png,jpg,jpeg,webp,svg}
*
```

Полные исключения каталогов стоят перед разрешениями. Это позволяет пропускать технические поддеревья. В других комбинациях разрешение вложенного файла может требовать обхода внешне исключенного каталога; такая папка не должна отсекаться преждевременно.
