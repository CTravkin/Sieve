# Требования Sieve

## Согласованный объем

- Основная функция — исключение файлов и каталогов перед индексацией хранилища Obsidian. Исключенные технические поддеревья должны отсекаться до чтения их содержимого, когда семантика разрешающих правил позволяет пропустить их целиком.
- Синтаксис и результаты сопоставления полностью повторяют Syncthing. Первоначальный эталон — 2.1.6: префиксы, маски, порядок правил, включаемые файлы, экранирование, нормализация и ошибки разбора. Совместимость подтверждается сравнением с нативным matcher, а не похожей библиотекой gitignore.
- Английский и русский обязательны. Переводы находятся в `src/locales/`. Для русского языка Obsidian используется RU, для всех остальных — EN.
- На основной странице настроек — краткая подсказка по синтаксису и действие открытия подробной справки. Syncthing упоминается только в подробной справке и документации GitHub.
- Описание на русском: «Исключает файлы и каталоги перед индексацией хранилища». Английский эквивалент: «Excludes files and folders before vault indexing».
- Сообщение несовместимости: «Эта версия Obsidian не поддерживает фильтрацию Sieve».
- Дополнительная функция — отображаемое имя текущего хранилища. Корневая папка не переименовывается.
- При переключении хранилищ меню должно показывать их кастомные названия, а не только подпись текущего vault. Путь и идентификатор каждого vault сохраняются.
- Настройки относятся к текущему хранилищу. Правила редактируются через UI или вручную в `<configDir>/plugins/sieve/data.json`, обычно `.obsidian/plugins/sieve/data.json`. Оба способа изменяют один источник данных; отдельный корневой файл правил не требуется. `#include` сохраняется как часть синтаксиса.
- Изменения правил применяются после полного повторного открытия хранилища. После успешного сохранения через UI предложить перезагрузить хранилище. Сохранение не означает, что новый набор правил уже применен.
- При сохранении измененного конфига хранить одну предыдущую рабочую версию, без истории бэкапов. При ошибке на следующем запуске использовать ее; если рабочей версии нет, открывать без фильтрации и показывать ошибку.

## Границы

Фильтрация не удаляет исходные файлы и не заменяет запись документов, переименование, работу с вложениями или синхронизацию. Конфигурация Obsidian должна оставаться доступной приложению и плагинам независимо от правил видимости.

Совместимость синтаксиса не дает приложению дополнительных файловых прав. Доступ к файлам `#include` ограничен возможностями платформы; для iOS необходимо отдельно проверить доступность всех нужных путей. Нельзя молча пропускать недоступный файл или неподдержанную конструкцию.

## Реализация и проверка

Исходники будущего плагина — TypeScript, устанавливаемый пакет — JavaScript. Общие модули не зависят от Node.js/Electron. Desktop и мобильный файловые адаптеры требуют отдельных интеграций; мобильный быстрый начальный обход нельзя считать отфильтрованным только по проверке настольной версии.

Проверки должны подтвердить начальный обход, файловые события, сохранение, переименование, вложения, повторный запуск и восстановление обычного поведения после отключения плагина. Отдельно сравниваются синтаксис с Syncthing и фактическое время запуска большого хранилища.

Стартовый менеджер хранилищ работает вне обычной страницы плагина. Область подмены имени и поведение до загрузки плагина остаются вопросом реализации; нельзя обещать замену имени во всех окнах без проверки.

## Текущая заготовка

Есть общий matcher с нативным oracle, ранний runtime с платформенными адаптерами и хранение настроек. Полный matcher подключен к начальной загрузке Obsidian на Windows. Интерфейс и отображаемые имена еще в работе. Объявленные в manifest платформы и минимум версии не заменяют отдельные нативные проверки.
