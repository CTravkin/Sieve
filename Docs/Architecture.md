# Архитектура Sieve

Общий matcher, ранний runtime, интерфейс настроек и отображаемые имена реализованы. Ниже отдельно описаны runtime и историческая диагностическая проба. Поддержка всех платформ не объявлена.

## Общий matcher и oracle

`src/core/matcher.ts` компилирует неизменяемый набор правил через `compileRules(text, context)`. Результат содержит matcher, revision и зависимости либо диагностику с источником, строкой и причиной; ошибочный набор не публикуется частично. `match` возвращает ignored, deletable, caseFolded и canSkipDir. Runtime не получает разрешения удалять файлы из признака deletable.

Виртуальная `.stignore` находится в корне vault. Include reader получает лексический путь, включая доступные пути вне корня; одинаковый realpath не служит глобальным основанием для дедупликации. Перед сопоставлением адаптер должен привести чистый относительный путь через `nativeNormalize`: NFC на Windows/Linux/Android, NFD на Darwin/iOS. Общий код использует фиксированные таблицы Unicode 17.0.0, без зависимости от ICU хоста и Node/Electron.

Эталон — неизмененные `lib/ignore` и `lib/scanner` Syncthing v2.1.6, commit `4461a1ce354d3990660966ad70176e00246adb61`; pin, glob replacement и native зависимости зафиксированы в [Oracle](../Tools/Oracle/README.md). Oracle пишет только в собственный sandbox с `os.Root`; preflight запрещает внешние alias targets и chmod через ссылки. Native oracle и его Go-зависимости не входят в пакет плагина.

Финальный корпус на Windows и Linux: 5952 fixtures, 34351 результат сопоставления с четырьмя флагами, 36674 сравнения нормализации и 66 scanner-деревьев без различий. Core включает четыре ограниченных subprocess-регрессии на допустимых масках около 64 КиБ: смешанные wildcard, чередование токенов, независимые группы и count/length ties. Исходный нативный порядок группировки сохранен; порт убирает повторные обходы и рекурсивное построение дерева.

Linux-запуск от codex uid 1000 на SPB-3: 38/38 тестов, без пропусков; архив `sieve-oracle-linux-final.tar.gz`, SHA-256 `47907982fb17a1df7435bee02ba665f3c98df23eb6850c4689e5bc7c526de7e6`. Собственный `/tmp/sieve-oracle-UJkYIc` удален. Windows пропускает два native Unix-сценария; они реально прошли на Linux. Отчеты принадлежат общим QA/Review/Ops CJA PC. Это проверка matcher, а не Obsidian на Linux или мобильном устройстве.

## Runtime и настройки

`src/main.ts` ожидает чтение vault-local настроек и всех `#include` в раннем `onload`, затем устанавливает instance hooks до первого `vault.load`. Подготовка ограничена десятью секундами. Позднее включение после layout требует повторного открытия: частичный пересмотр уже загруженного индекса не выполняется.

Desktop guards применяют полный matcher перед рекурсивным обходом и reconcile. Путь конфигурации Obsidian доступен независимо от правил. Каталог с `canSkipDir` отсекается до I/O; разрешающие правила могут требовать обхода исключенного контейнера. Прямые чтение, запись и файловые операции остаются нативными.

Проекция индекса отделена от физического кеша адаптера. Удержанный `TFile` получает новые пути и stat при физическом rename/modify даже после исключения. Это сохраняет запись через удержанную ссылку и обычное поведение редактора. Реальное удаление файла сохраняет поведение хоста. Metadata, lookup и link queue должны учитывать текущую видимость; отдельные source-model проверки не заменяют наблюдения в приложении.

Mobile-кандидат заменяет начальный массовый `watchAndStatAll` на наблюдение корня и управляемый обход через адаптер. Это гипотеза по установленному bundle и API, проверенная моделью адаптера, без подтверждения на устройстве. Неподдерживаемые private capabilities не получают частичный набор hooks. При общей runtime-ошибке собственные hooks снимаются; исходный результат операции сохраняется, повторного выполнения нет. Для восстановления полного индекса требуется переоткрытие, ошибка остается видимой. Автоматический нативный обход без фильтра выполняется только при сбое управляемого начального mobile scan.

`src/settings/storage.ts` хранит `{schemaVersion: 1, rules, displayName}` в `<configDir>/plugins/sieve/data.json`. Draft, saved и примененная конфигурация различаются. Save сначала проверяет правила и все includes; сохраняет одну предыдущую подтвержденную рабочую конфигурацию в `data.previous.json`, затем новое значение. Снимок содержит исходные байты includes, поэтому fallback не зависит от поврежденного текущего include. Повторное сохранение неизменных настроек и includes не создает записей. При ошибке загрузки используется валидный предыдущий снимок; без него vault открывается без фильтрации с сообщением.

Изменения правил применяются после полного повторного открытия. При ручной правке во время работы предыдущая активная конфигурация может быть сохранена; офлайн-правка не позволяет восстановить утраченную рабочую версию, если предыдущего снимка еще нет. Отключение снимает hooks, но полный индекс возвращается после переоткрытия.

`src/ui/settings-tab.ts` использует нативные controls Obsidian и различает draft/saved/active. Save проверяет правила до записи и предлагает Reload/Later без автоматической перезагрузки. Пока startup не завершен, поля и Save заблокированы; API также отклоняет раннее сохранение. Внешние изменения доставляются через публичный `Plugin.onExternalSettingsChange`; локальные правки формы сохраняются отдельно. Статусы и коды ошибок локализованы, исходные внутренние причины не выводятся. Диагностика `isRoot` отличает корневые правила UI от настоящего включенного файла `.stignore`.

Справка использует те же импортируемые Markdown-файлы RU/EN, что документация, и открывается без сети. Язык выбирает `getLanguage`: только `ru` дает RU, остальные значения — EN. UI-модель, доступные имена controls, loading/dispose, invalid Save и Later проверяются отдельно от нативной геометрии и поведения приложения. Windows native UI проверен на сборке 10, обновление и automatic external hook/clean-dirty hydration — адресно на сборке 12; исходные документы и пакеты сохранены.

## Отображаемые имена

`src/alias/projection.ts` меняет только доступные UI-поверхности: подпись, результат `getAppTitle`, drawer и native chooser двух команд. `Vault.getName`, adapter, `app.title`, пути, ID/URI и callbacks не заменяются. Имя текущего vault берется из принятой рабочей конфигурации; successful Save обновляет UI без смены active rules. Чужие configs читаются только для имени с проверкой схемы.

Desktop provider в ленивом `desktop.ts` использует native IPC registry и authoritative configDir. Один snapshot/index обслуживает projection, перед dispatch выполняется одна повторная проверка. Одна projection читает до четырех configs одновременно с общим deadline; отмена/закрытие не запускает новые чтения. Начатый native Promise может завершиться позже и не применит UI. Пустые/ошибочные/недоступные имена возвращают native подпись.

Drawer replay сохраняет native handler и меняет `MenuItem.titleEl` до native conversion. При изменении registry открывается свежее native меню с исходными именами. Захват `FuzzySuggestModal.prototype.open` действует только на синхронном стеке нужной команды; далее проекция ограничена ее instance. Закрытие menu/chooser/popout и unload снимают собственные references/observers/wrappers, сохраняя чужие последующие обертки. Модель покрывает native timing, paths/callbacks, Unicode/HTML, поиск и cancellation; native результаты описываются отдельно.

## Нативный runtime на Windows

Приватный кандидат `0.4.5 (9)` установлен только в шесть синтетических vault Obsidian API 1.14.4, по 1104 исходных файла. В каждом завершены ранняя загрузка, обход и layout; trace не усечен.

| Вариант | Index | Metadata | I/O адаптера в Technical |
| --- | ---: | ---: | ---: |
| Baseline | 1119 | 1104 | 1262 |
| Исключен Technical | 106 | 103 | 0 |
| Разрешен Technical/deep/keep.md | 109 | 104 | 1025 |
| Sieve первый / последний | 106 | 103 | 0 |
| Alternate configDir | 106 | 103 | 0 |

Вариант с разрешенным потомком использует консервативный `CanSkipDir` полного matcher: требуется обход контейнера. Пять вызовов I/O исторической prefix-пробы не являются ожидаемым результатом этого набора правил. Счетчики Baseline могут меняться с состоянием metadata и watcher; таблица описывает один сохраненный trace, не benchmark.

Прошли 13 нативных событий: запись и переносы через удержанные ссылки, внешняя правка/atomic replace, вложение, файл и папка, NBSP/NFD, реальный Markdown editor с положительным контролем autosave, сохранение dirty buffer после исключающего rename и реальное удаление скрытого открытого файла. Дополнительная проверка подтвердила пустую проекцию внутри callbacks, удаление старых FileExplorer keys, один create исходного объекта при возврате и свежие итоговые cache/content/links после последовательной очереди и ABA. Новое внешнее изменение скрытого файла не ставит metadata read/parse; физический объект и его stat сохраняются для редактора.

Ранее начатая работа с видимым файлом остается в нативной очереди. Промежуточный старый результат до свежего встречается и в видимом контрольном сценарии; проверяется итог после опустошения очереди. Новая система поколений или замена файловой записи не добавлена. Модель адаптеров: 52/52; хранение: 14/14. Это не нативное подтверждение mobile.

## Историческая desktop-проба

На нативном Windows Obsidian API 1.14.4 заранее включенная community-проба завершает async `onload` до первого `vault.load`. В пробе подготовка задерживалась на 100 ms; журнал подтвердил hooks-ready → onload-end → vault-load-start → adapter.listAll → layout-ready.

Desktop-адаптер содержит `listAll`, `listRecursive`, `listRecursiveChild(parent, name)`, `reconcileFile(realPath, normalizedPath)` и `reconcileFileInternal(realPath, normalizedPath)`. Mobile-метод `watchAndList` отсутствует на desktop: проверять его как общий capability нельзя.

Instance guards `listRecursiveChild` и `reconcileFile` отсекают путь до raw; дополнительный guard `reconcileFileInternal` — до lstat. `fsPromises` клонируется только для инструментирования данного адаптера, общий node:fs не меняется. Direct read/write не фильтруются. При unload свои свойства восстанавливаются; сохраненный чужим wrapper hook становится неактивным.

Временный классификатор работает по префиксам fixture и явному разрешенному потомку. Он сохраняет необходимые контейнеры. Это проверка точки интеграции, а не реализация Syncthing или его CanSkipDir. Production matcher остается самостоятельным этапом с native oracle.

Установленный obsidian.asar не изменялся.

Счетчики относятся к `fsPromises` адаптера после установки hooks. Это не трассировка всех системных вызовов ОС, сторонних плагинов или native watcher. Проверочные повторные запуски не являются контролируемым cold/warm benchmark; ускорение в процентах не заявляется.

Raw отчеты и inventory находятся в игнорируемом `Local/.temp/SieveProbe/2026-10-13T20-24-47-623Z/`. Финальная проба `0.2.0 (2)`, SHA-256 main.js `abd985e02968e8a1f27b6b39ff3a23ee517ee0980068c1e0f14b64b823f95dce`. ## Оставшиеся гейты

Нужны repeated cold/warm измерения, OS/native watcher trace, проверка alias и native mobile fast/fallback/resume. Две очередности community plugins и alternate configDir прошли на Windows. Constantine разрешил продолжать общий движок и исследовать недоступные платформы по API/коду с явными гипотезами. Это не заменяет native доказательства из [плана](../Plans/Development.md).

На Windows нативная проверка событий кандидата 0.3.0 обнаружила обход reconcile при `adapter.rename`. Проба теперь передает исходное событие rename, чтобы сохраненные TFile-ссылки получили новый путь, затем вызывает внутренний `adapter.removeFile`: он убирает запись из памяти, не удаляет файл с диска. Создание, сохранение, rename, перенос файла и папки с потомком в исключенный каталог, сохранение через удержанные ссылки, внешний перенос обратно/правка/создание, чтение и удаление тестового вложения прошли. Временные файлы удалены и исчезли из индекса. Отчет: `Local/.temp/SieveProbe/2026-10-13T21-29-37-211Z/events-folders.json`. UI редактора этим сценарием не проверен.

В этом run варианты SieveFirst/SieveLast реально загрузили sentinel после/до Sieve, сохранив ранний guard: индекс 106, metadata 103, Technical I/O адаптера 0, полный trace. Alternate выбрал `.sieve-config` через localStorage только отдельного профиля; плагин загрузился из него при правилах, исключающих этот configDir. Те же счетчики подтвердили bypass конфигурации. SHA-256 всех 6624 исходных документов совпали; hash установленного obsidian.asar прежний. Наблюдаемый интервал `vault.load` записывается отдельно от времени UI «Reading files» и сам по себе не является benchmark.

Статическая проверка того же bundle установила: desktop меню берет `vault-list` по IPC и вычисляет basename каждого пути; mobile select берет name/location списка vault. Обертка `Vault.getName` не заменит названия всех пунктов. Требуемая проекция alias должна читать данные соответствующих vault и менять только UI-метки, сохраняя значения путей и IDs; native работа alias еще не проверена.

Системная FileIO-трасса WPR недоступна с текущими правами: запуск вернул Access denied, `0x80070005`; сессия не создана, состояние до/после — not recording. Не изменялись права и настройки ОС. На BUF-2 и SPB-3 read-only проверка не нашла Obsidian/Xvfb в проверенных стандартных путях, графические службы неактивны. Нестандартные установки не исключены; native Linux остается NOT_TESTED.
